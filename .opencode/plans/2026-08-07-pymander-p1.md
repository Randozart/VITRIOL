# Pymander P1 — Store + Ingest + Selection

Date: 2026-08-07.

## 1. Goal

Implement P1 of `2026-08-06-pymander-ascensus.md`: the Pymander **reference mind**
store and its ingest path. Pymander is the static, curated, domain-specific knowledge
basis — *how we do a domain well* — distinct from Hermetis (episodic: *what happened*).

This phase is buildable now (no GPU required — it reuses the running Hermetis db
machinery and the embed server, both already up on :8090/:8081).

## 2. Scope (P1)

1. **Per-domain node namespace** — reuse Hermetis `db.py` (`store_node`, embedding
   cache, versioned `git_rev` supersede). Each domain is a distinct Hermetis memory
   root: `~/.vitriol/pymander/<domain>/memory.db`.
2. **Ingest/author tool** — a CLI (`vitriol pymander ...`) + Python module
   (`libvitriol/pymander.py`) that turns a markdown corpus into atomic nodes
   (one `## heading` → one node `summary`), embeds best-effort, versioned by
   `git_rev` (supersede-new, never hard-discard — matches `db.store_node`).
3. **Per-project selection config** — which domains are active for a project,
   persisted to `~/.vitriol/pymander/selection.json` (map project_id → [domain]).

Out of scope for P1 (deferred to P2): doctrine injection into the window, the
`pymander` opencode tool, Ascensus, promotion path. The store/search primitive is
built in the module (via `retrieval.retrieve`) but CLI `search`/tool wiring is P2.

## 3. Rationale / evidence

- `libvitriol/hermetis/db.py:317 store_node` already does versioned-supersede + embed
  cache (`db.py:207 _compute_and_cache`?). Reuse, don't reimplement (AGENTS DRY).
- `_get_db_path` (`db.py:39`) = `MEMORY_DIR/<project_id>/memory.db`; a project_id of
  `pymander/<domain>` yields exactly `~/.vitriol/pymander/<domain>/memory.db`.
  Domain name sanitised (no `/`, `..`, control chars) before use.
- Node embed via `hermetis.embed.encode` (GPU GGUF :8081) best-effort; falls back to
  keyword scoring when the embed server is unreachable (see `embed.is_available`).
- Module is Python (reuses the live Hermetis db machinery). CLI wired through the
  existing `scripts/vitriol` bash (consistent with `tui`/`config` subcommands).
