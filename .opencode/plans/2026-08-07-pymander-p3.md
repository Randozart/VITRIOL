# Pymander P3 — Ascensus (cloud escalation)

Date: 2026-08-07.

## 1. Goal

Give the model the ability to escalate genuinely-hard inquiries to a configured
cloud model (Google Gemini) that "takes over the wheel" — the reliability valve
of the closed-loop architecture (see `2026-08-06-pymander-ascensus.md` §2).

## 2. Scope

1. **`ascensus` opencode tool** (Copula plugin): takes the user query + the local
   model's reasoning attempt; calls Gemini; returns the cloud answer.
2. **Replace protocol (phase 1: model-finalizes)**: the tool returns the cloud
   answer as tool output; the local model emits it as its response. No secrets or
   credentialed code sent (only the query + reasoning text).
3. **Learning loop**: good Ascensus answers are stored into Hermetis (episodic,
   `role: tool`) and become candidates for Pymander promotion (P4) — escalation
   self-reduces over time.
4. **Flagging**: escalation is visible (log line + tagged store) so the user can
   audit when the cloud was consulted.

## 3. Evidence

- `plugins/copula.ts` already has a `tool:` section (memory_search,
  pymander_search) — Ascensus joins it.
- `GEMINI_API_KEY` read from env at runtime; tool returns a clear "not
  configured" message when missing — never crashes the session.
- Gemini text-gen API: `https://generativelanguage.googleapis.com/v1beta/models/
  {model}:generateContent?key=...` (public spec, documented for LLM agents).
  Model default `gemini-2.5-flash` (cheap; escalation should fire rarely).

## 4. Design decisions

- **Local-only content**: only the query + the local reasoning text leave the
  machine. No file contents, no credentials, no code with secrets.
- **Store as tool episode** so Hermetis learns from the escalation (learning loop
  part 1). Promotion to Pymander corpus is P4.
- **Env-configurable**: `GEMINI_API_KEY`, `GEMINI_MODEL`, optional `GEMINI_MAX
  TOKENS`. Escalation flag in the stored content (`[ascensus]`).

## 5. Tests

- Plugin TS not unit-testable here; manual path verified via curl against the
  Gemini API with the user's key when available.
- Hermetis learning loop: verified by the existing `/hermetis/store` path
  (tool role) — no new server code needed.

## 6. Results

- **`ascensus` tool** added to `plugins/copula.ts` (synced to installed
  `~/.config/opencode/plugins/`): Gemini text-gen via
  `generateContent`, `GEMINI_API_KEY`/`GEMINI_MODEL`/`GEMINI_MAX_TOKENS` from env.
  Reads only the query + optional local reasoning — no file/secret content.
  Returns a clear "not configured" message when the key is unset (graceful).
  Learning loop: stores `[ascensus] model=… query → answer` to Hermetis.
- Replace-protocol phase 1 (model-finalizes): the tool returns the cloud answer
  as its output; the model emits it verbatim. Phase 2 (direct-inject) deferred
  until we observe the local model corrupting good answers.
- **Not live-verified** (no `GEMINI_API_KEY` in env yet). Code path + options
  confirmed against the public Gemini API contract.

## 7. Risks

- No key in env yet → tool degrades gracefully; user must export
  `GEMINI_API_KEY` to activate.
- Cost: acceptable because escalation fires rarely (occasional, per design).
