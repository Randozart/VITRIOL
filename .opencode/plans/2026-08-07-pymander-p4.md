# Pymander P4 — Sample corpus + proof

Date: 2026-08-07.

## 1. Goal

Prove the Pymander value: a hand-authored systems-programming corpus, a **bias
effect** measurement (doctrine changes the model's behavior for the better in a
domain), a **real Ascensus escalation**, and the **learning loop** (a good cloud
answer lands in Hermetis and is promotable into the corpus, so escalation
self-reduces).

## 2. Scope

1. **Corpus**: grow `docs/pymander/systems-programming.md` into a real,
   license-clean, hand-authored systems-programming doctrine (memory safety,
   zero-copy, ternary/LUT execution, concurrency, the VITRIOL domain).
2. **Bias-effect A/B test**: same task, with vs without a `[Pymander doctrine]`
   block; measure a concrete behavioral delta (e.g. the model chooses the
   doctrine-prescribed pattern). Evidence: prompt pairs + both outputs + a
   scoring rubric; record in the plan.
3. **Escalation**: fire the `ascensus` tool on one genuinely-hard query;
   record the cloud answer (requires `GEMINI_API_KEY`).
4. **Learning loop**: the stored `[ascensus]` episode becomes a Pymander
   promotion *candidate* (curated; user decides what lands — no auto-merge).

## 4. Design decisions

- Bias test compares the doctored vs. doctor's-presence output on the SAME
  prompt; delta must be attributable to doctrine, not noise. Record both, with
  rubric + a clear verdict per item.
- Promotion stays **curated** (AGENTS: quality + license-clean): a candidate
  file lists cloud answers worth folding; the user approves; then re-ingest.
