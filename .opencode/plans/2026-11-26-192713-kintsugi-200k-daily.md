# kintsugi-200k-daily

## Purpose

Qualify a Kintsugi window of at least 200,000 tokens for daily programming.

## Approach and alternatives

Compare the same-host reference launch with the current VITRIOL launcher. Try a 229376-token isolated profile, beginning with tiered KV and minimal GPU pressure. Require a filled coding prompt near the observed 92K session and a deep recall control before calling it daily-ready.

- The existing 65K profile is the speed and rollback baseline. A split or no-draft profile may buy capacity but must be measured for coding latency. Do not infer usable depth from successful startup.

## Scope and documentation

Read-only review and isolated qualification. The initial GPU0 experiments preserve the live GPU1 engine. The operator subsequently authorized a GPU1 maintenance window for the same-host comparison. The wrapper restores the production profile, autosave and GPU0 decision endpoint when testing ends. A selectable profile requires acceptable runtime evidence.

## Invariants

1. GPU0-only trials preserve the live GPU1 service. During authorized GPU1 downtime, the test uses a separate port and slot, and exit restores the previous production profile, endpoints and autosave.
2. Qualify 229,376 advertised tokens separately from measured depth. Record actual prompt tokens, recall, decode and prefix reuse; the launcher preserves full argv in every run.
3. A promoted profile needs an acceptable latency and VRAM margin on its intended placement. Mixed-placement capacity results alone do not qualify the existing GPU1 daily driver.

## Verification

- Record fingerprints, exact filled input tokens, recall result, prefill and decode speed, warm reuse, GPU/host headroom, and live service continuity. A load OOM, recall error, unacceptable slowdown or startup stall falsifies a daily-driver candidate.
