## Metrics (per arm)
1. Decode t/s: greedy, n_predict=128, temp 0, median of 3 runs (`predicted_per_second`).
2. Prefill: 2048-token filler, `prompt_per_second`.
3. Correctness: 8-prompt suite, 1 round (pass = sane answers; checker artifact known).
4. Cold vs warm: fresh engine start vs after ~5 min generation (page-cache effect on B arms).
5. Resources: free -g during run (RAM/swap), nvidia-smi VRAM.
6. Verified-binary protocol every arm: strings on the .so/binary for expected probe markers
   (ik: "iqk"; ours: VITRIOL_NH_ENTER etc.) before any number is recorded.

## Decision gates
- **GSQ-RCO:** A1 ≥ A2 +10% (MTP parity) → pillage ik's winning kernels into our fork behind
  gates. A1 ≥ A2 +30% → evaluate switching engines entirely (session router + kvtier port to
  ik's server layer; our router is server-layer code, ik's server is same lineage).
- **Flash-Next streaming:** B1 vs B2 t/s + correctness = THE KILLER EXPERIMENT (rule in
  gateb-close-perf doc: VITRIOL ≥1.3x → fix the 16-cliff with justification; within ~20% ->
  adopt upstream-style offload, shelve the custom store).
- **GLM-5.3-Flash:** any arm ≥5 t/s coherent output -> viable local large-MoE for the user;
  feed the quality verdict back (user judges).
- Any ik win also yields a pillage list itemization (which PRs to port) recorded here.
