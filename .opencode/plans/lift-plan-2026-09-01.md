## Phase C — weight-surgery pipeline (the capability experiment)

**Goal**: a smaller *effective* model at equal VRAM = more certified depth.
Mechanism available today (rewrite.rs): **magnitude masking** — zero the
lowest-magnitude weights inside maskable tensors, seeded and ratio-controlled.
Expert-count reduction (DISSOLVE) is explicitly OUT of scope this pass
(requires n_expert metadata surgery — separate project).

**Surface**: `vitriol` CLI subcommands (scripts/vitriol already dispatches to
the Rust binary). The disabled TUI Officina tab stays untouched.

1. **`vitriol census <model>`** — expose census.rs: per-tensor dead-lane %,
   abs_mean, entropy; group `ffn_*_exps` tensors by layer; emit a dross
   score ranking + `--emit-plan <json>` (candidate tensors + ratios).
   Output: human table + JSON sidecar.
2. **`vitriol rectify <model> --plan <json> --out <path>`** — wraps
   plan/copy_and_edit/mask_*: surgical COPY only (the source model file is
   never touched). Structural re-validation after write (GGUF re-parse,
   tensor count/shapes, `vitriol calibrate --quick` as the free parser check).
3. **Validation gates** (each variant must pass ALL, else discard):
   - Perplexity: stock vs variant on a fixed small corpus (wikitext-2 test),
     `llama-perplexity` binary (build the cmake target first — impl lib
     exists, standalone binary missing).
   - Speed: sweep_controller.py bench (64-tok gen, 1 warmup + 3 rounds) at
     the live shape (22,14, ctx 81920, parallel 2).
4. **Acceptance thresholds (proposed defaults)**:
   - Δ perplexity ≤ **+2% relative** vs stock
   - t/s ≥ **stock − 3%**
   - VRAM at load strictly ≤ stock (the whole point)
5. **`scripts/surgery-campaign.sh`** — census the live model → emit 3
   variants (mask ratios ~2% / 5% / 10% targeted at the dross-score
   bottom of FFN-expert tensors) → run all gates → summary table with a
   recommended winner (or "none pass").
6. **Promotion policy**: a winning variant becomes a *profile candidate*
   (`vitriol config` pointing at the pruned copy). The LIVE config is never
   swapped automatically — owner sign-off required (one command, explicit).

**First target**: `~/Downloads/Qwen3.8-27B-Q3_K_M.gguf` (the live model,
13.8 GiB; 384 GiB disk headroom = ample for copies).
