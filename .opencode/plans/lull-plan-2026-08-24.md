## 0. Mission

One mechanism serving two product goals:

1. **Standalone Qwen3.8-27B** (`~/Downloads/Qwen3.8-27B-Q3_K_M.gguf`, qwen35 arch,
   RTX 3060 + GTX 1070 Ti): run **longer** (effective context beyond the 262144 native
   ceiling via spill) and **faster at depth** (score-driven eviction permanently masks
   evicted cells → attention reads fewer keys as context grows).
2. **REBIS** (Sol/Luna dual-head co-residency): spill drafter cold KV to pinned host RAM
   so the verifier gains VRAM headroom; optionally file-back server checkpoints.

Non-goals: replacing FlashAttention kernels, upstreaming anything, touching Rebis files.

## 2. Architecture

### 2.1 Core idea — the attention probe

FlashAttention never materializes attention probabilities, so exact H2O scores are not
directly available. Instead we compute them *off the critical path* with a small
**probe graph**, executed on the sibling GPU while the other GPU owns the current
pipeline split (the "lull"):

```
per probe (every VITRIOL_KV_SCORE_EVERY decode steps):
  for each full-attn layer il (16 of 65 for qwen35):
      s_il = Σ_heads softmax(q_last · K_ilᵀ / √d_k)   over cached cells (stock ggml ops)
  scores[cell] ← λ·scores[cell] + s_il                (exponential decay accumulation)
```

- q capture: stash last decoded token's per-layer q at attention input (~24×256 f16
  ≈ 12 KiB/layer; 16 layers ≈ 200 KiB total). MTP draft tokens are excluded — trunk /
  verified tokens only.
- Probe cost: reading K of all FA layers @131k q4_0 ≈ 1.15 GiB → ~3 ms on either GPU;
  amortized over N≥16 tokens it is noise. Score download D2H = 131k floats ≈ 512 KiB.
- Probe graph uses stock ggml ops (`mul_mat`, `soft_max`, scatter-add via `set_rows`
  or host-side apply after D2H). GEMV-shaped — fine on sm_61 without MMA paths.

### 2.2 Execution model / lull scheduling

Sched splits run strictly sequentially (GPU0 computes its shard, then GPU1), so each
device idles during the other's split. LULL enqueues maintenance work on a **low
priority, non-blocking stream** per device (pattern proven by `g_lru_stream`), chained
with CUevents so it can never delay the next split. CPU-side score bookkeeping happens
on the probe-download completion callback path (tiny).

### 2.3 Eviction policy (Phase 2)

`evict_sparse()` upgrades from blind to score-driven:

```
keep:    first n_sinks cells (sink preservation, StreamingLLM idea)
         most recent W cells (W = 2 × n_needed default)
evict:   lowest accumulated score first, only when find_slot() fails
         (demand-driven; no periodic churn)
```

Evicted cells are metadata-freed (`cells.rm()`); their stale data is simply masked out
of future attention (existing kq-mask behavior). This is why eviction needs no GPU
kernel — and why masking evicted keys makes deep-context decode *faster*.

### 2.4 Tiered spill (Phase 4)

```
hot set  : VRAM KV buffer (unchanged layout)
cold set : lowest-scored cells outside recent window
           → async D2H into pinned host shadow buffers, rate-limited
restore  : prefix rewind / seq reuse triggers batched H2D prefetch;
           inter-turn gaps in REBIS agent loops hide restore latency
budget   : background PCIe traffic capped (default 100 MB/s) so sharded-layer
           activation traffic is never starved (measured, not guessed)
```

Replaces `VITRIOL_KV_MODE=offload`'s all-or-nothing behavior with `tiered`.
Optional: server checkpoints (server-context.cpp:1915 `create_checkpoint`) gain a
file-backed mode instead of anon-RAM growth (ties to docs/rebis/memory-model.md).

## 4. Risks & mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Probe ≈ approximation of true H2O (sampled softmax) | Quality drift | full-key probes (not sampled) v1; decay tuning; ppl gate before eviction enabled |
| sm_61 kernel coverage for probe ops | Probe fails on 1070 Ti | stock ggml GEMV/dequant paths only; smoke-test both devices individually |
| Background PCIe starves inter-GPU activations | t/s collapse | rate budget + Phase 0 numbers; spill only during verified idle windows |
| Multi-stream (REBIS n_stream>1) score bookkeeping | Wrong-cell eviction | scores are per-stream in `v_cells[s]`; probe applies per stream id; test multi-seq |
| MTP draft tokens polluting q capture | Garbage scores | capture at trunk attention input only; assert draft-excluded |
| Concurrent Rebis agent drifts submodule base | Merge pain | rebase `lull-kv` onto `vitriol-mellum2` before each integration; keep diffs tight |
| Fresh-worktree build breaks (arch flags) | Lost time | configure with `CMAKE_CUDA_ARCHITECTURES="61;86"` from the start |
