# MTP A/B — draft_n_max 2 vs 3 (2026-11-11)

## Verdict: **mtp2 wins** — `draft_n_max = 2` is the daily driver.

The 3rd draft token is net negative on the BuffedMod-Q6K build: its
acceptance is so low that the speculative round pays for it. mtp3's
*mean draft length* is higher (3.2) but most of that length is rejected,
so per accepted token it is slower.

## Method (same binary, same model, comparable depth)

- Model: `~/Models/Qwen3.8-27B-GSQ-RCO-BuffedMod-IQ3_S_XL-mtp-Q6K.gguf`
- Config: ts 27,21, q4_0 KV, cache8, ctx 262144, MTP on, adaptive_k=0.
- Both arms LCP-restored to ~70–72k depth (`f_sim_best ≈ 0.99`) so the
  comparison is at filled depth, not shallow.
- Signal: `print_timing` `eval time` + `draft acceptance` lines in
  `/tmp/opencode/vitriol_gen.log`.

## Numbers (filled depth, ~70–72k)

| arm | eval t/s | tg / tg_3s | draft acceptance | mean len |
|---|---|---|---|---|
| **mtp3** (n_max=3) | 23.14 / 22.86 | 22.74 / 22.86 | **0.735** (75/102), 0.704 (57/81) | 3.21 / 3.11 |
| **mtp2** (n_max=2) | 23.76 / 22.91 | 23.85 / 22.91 | **0.953** (101/106), 0.925 (37/40) | 2.91 / 2.85 |

- mtp2 raw acceptance ≈ **+22 pt** (0.953 vs 0.735).
- Eval t/s roughly flat (23.8 vs 23.1); mtp3's advantage is illusory —
  it spends tokens drafting the 3rd position that mostly fails.

## Applied

- `~/.vitriol/config` now carries `draft_n_max = 2`
  (profile `qwen38-buffedmod-262k-cache8-mtp2`), live after the second
  restart. Fingerprint rides `spec=mtp:2`.
- Keep `qwen38-buffedmod-262k-cache8-mtp3` on disk for rollback/A-B reuse.

## Note vs the 2026-09-28 "n=3 +17%" note

That +17% was measured in an earlier build/era at 42.7k depth. This
A/B at ~70k on the current BuffedMod-Q6K build flips it: the marginal
3rd draft token no longer pays. Draft-depth optimum is
build- and depth-sensitive; re-certify after any model or MTP-engine
change. The `adaptive_k` trim (off here) is the other lever if 3 ever
needs to be useful again.
