## Goal

Run Qwen3.8-27B Q3_K_M through VITRIOL and drive it with Hermes Agent (the
same harness that uses Mellum2), verifying tool-calling, the SWA tool-reminder,
and the get_tool_capabilities tool all work with the Qwen3.8 architecture.

## Results

### Tool-calling works
- Plain question ("What is 2+2?") → "4", no tool call. ✓
- Tool request → proper structured call: `search_files {"pattern":"*.md",
  "target":"files","path":".../briev-lang"}`. ✓
- **Agentic behavior**: model paginated search_files 7 times (offset
  0→50→100→150→200→250→500) with correct args each time, finding 500 .md
  files in briev-lang. ✓

### SWA tool-reminder works at long context
- Qwen35 is a **hybrid** arch (full + sliding-window attention), so the same
  SWA concern as Mellum2 applies.
- At 4505 prompt tokens (past SWA-1024), model still called
  `read_file {"path":"/etc/hostname"}` — tool awareness persists. ✓
- Reminder injection confirmed (fired), text: "Note: tools available in this
  environment (call one only if the user's request needs it): ..."

### Trigger-marker detection (important finding)
- My reminder auto-detects the trigger from template source, checking
  `<tool_call>` first then `[TOOL_CALLS]`.
- Qwen3.8's actual `grammar_triggers` in the rendered prompt is
  `<tool_call>\n` — NOT `[TOOL_CALLS]` (that path is the Ministral template,
  chat.cpp:927). So the reminder correctly picked `<tool_call>`, and the tool
  call succeeded as structured output. Detection is correct. ✓

### get_tool_capabilities
- Registered in the hermes `coding` toolset; available in the session.
- (Not exercised as a call in this run — Qwen produced correct args without
  needing it, but it remains as the schema-accuracy safety net.)
