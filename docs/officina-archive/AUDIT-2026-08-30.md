## CRITICAL — would bite in daily use, or violates our own constitution

### F1 — The concurrency cap is an illusion for `tris go` **[verified by design] — FIXED 2026-08-30**

The dispatch semaphore (`TRIS_MAX_CONCURRENT_LC`, default 3) lives inside
the vitriol-bridge Python module. `tris go` starts a fresh Python process
per invocation: module imported, semaphore created, one dispatch run,
process exits — semaphore state evaporates. Three concurrent `tris go` =
three simultaneous sub-coders with no memory of each other. The KV gate
cannot compensate (it runs "kv-unknown → pass" on this engine build).

**Fix:** cross-process file lock (`flock`) in the state dir, replacing or
supplementing the semaphore; contention test that spawns two real processes
and proves the second is refused.

**DISPOSITION: FIXED 2026-08-30** — engine.acquire_dispatch_slot(N): N
flock'd slot files under `<state>/locks/`, first-free-wins, idx-tracked
release (fd close on every path incl. subprocess timeout). The in-process
semaphore is GONE — handle_dispatch refuses when all slots are held.
Verified with REAL process contention: child process holds the only slot
→ second process REFUSED → after holder exits, slot re-acquirable (2
tests + full suite 44 pass).

### F2 — The supervisor silently overrides profile policy **[verified live]**

`vitriol-server.service` carries `Environment=VITRIOL_KV_SCORE=probe`
and `Environment=VITRIOL_POOL_RESET=1`. The launcher resolves env > profile
(`VITRIOL_KV_SCORE:-…CFG`), so the smoke profile's declared `score = off`
is overridden — the unit-run fingerprint says `score=probe pool_reset=1`.
Single-source-of-truth violation (Layer Interface Protocol), hidden unless
someone diffs fingerprints against profiles.

**Fix:** minimize unit Environment to process-management only (OOM, restart
mechanics), dated comment + undo note in the unit file, daemon-reload, and
a fingerprint-vs-profile consistency check in `tris status`.

### F3 — Metrics-delta accounting is only valid with zero concurrent consumers — **FIXED 2026-08-30**

Ledger `tok_in/tok_out` = `/metrics` counter deltas around a task. Any
concurrent engine traffic (Hermes turn, manual curl, second dispatch) folds
into the numbers. Daily use is exactly the concurrent case, so the shipped
accounting cannot survive real usage.

**Fix (architectural):** ledger must prefer consumer-side accounting —
Hermes `--usage-file` (built for exactly this) and little-coder per-message
session usage; metrics deltas demoted to sanity check. Resolves F15 too.

**DISPOSITION: FIXED 2026-08-30** — bridge spawns dispatches into a
deterministic per-run `--session-dir` and parses pi's per-message usage
(`{input, output, cacheRead, cacheWrite, reasoning}`, shape verified
against a live session); `tris go` writes `accounting: session-usage` rows
(tok_in = non-cached processed, cache_read = prefix-reused, api_calls);
engine deltas ride along as `sanity_metrics` only. `tris ledger-ingest
<usage.json>` ingests Hermes `--usage-file` reports into the same
vocabulary. 32 bridge tests + live proof (accounting rows show per-call
cache hits the old approach could never see). Bonus measurement: pi base
prompt 6,427 tok vs Hermes 19,953 — the diet target validated from a
second independent surface. F15 resolved with it.

### F4 — Budget table (§R2.8) contradicts measured reality; no amendment exists

Rule 1: the table is the specification; changes require a dated report
amendment. Measured since the table was written: Hermes fixed overhead
~20K tok on a trivial turn; a hard 64K engine-window floor. Neither is a
table row. Until amended, the constitution disagrees with its own evidence
— and per Rule 14 side documents may not silently rewrite it.

**Fix:** dated amendment in REPORT-02 (or new dated report) reconciling the
table with measurements; gateway base-prompt becomes an explicit row. The
prompt diet (fixed ≤ 8K) is then the plan that brings reality back to the
amended table.

### F5 — VRAM arithmetic likely fails the CERT boot (untested)

`mtp-131k` runs c=131072. Vision adds mmproj-F16 (931 MB on disk + resident
activation memory) + image prefill buffers on top of ~12.4 GB weights and
131K q4_0 KV across a 20 GB split — plausibly instant OOM at first boot,
turning the five-minute reboot into a debug session.

**Fix (pre-boot):** honest arithmetic for 96K/131K ± projector; prepare a
text-only fallback profile; treat `vis=on` as a claim to verify at boot,
not an assumption. Actual proof needs hardware; the preparation does not.

## STRUCTURAL — design debt; schedule in a hardening sprint

### F6 — Unbounded growth, no GC story **[partially verified: 433 MB already]**

Checkpoints: 433 MB on disk (autosave unit, every 300 s). Snapshot refs: no
pruning — the `maxSnapshots` field was dropped in the snapshot rewrite and
never replaced. `events.jsonl`, `ledger.jsonl`, `.pi/rtk/*.log`: append-only,
no rotation. Each reasonable alone; together they guarantee bloat over
months.

**Fix:** one retention policy (per-source caps: count/bytes/age), executed
by a maintenance pass in `tris up`, documented in RULES-CACHE-POLICY.

### F7 — Two checkpoint writers + unverified boot-restore mismatch window

Autosave unit writes `~/.vitriol/checkpoints` (own naming) and **restores
at boot**; our extension writes a per-profile subdir under
`<stem>-turn-N.bin`. Consequences: same logical state in two namespaces
(double disk, split truth), and the unit's boot restore may restore a slot
saved under a *different model* if the profile changed between sessions —
engine behavior in that case is untested. Our `restoreIsCompatible` guard
protects only our path, not the unit's.

**Fix:** one namespace owner; boot-restore must pass the same model guard.

### F8 — praetor pre-commit hook exists only in trismegistus **[verified]**

little-coder and VITRIOL have no non-sample git hooks; "praetor gates
commits" there is enforced only by manual discipline.

**Fix:** install the hooks (trivial) or document the gate as manual in those
repos. Choose one; do not leave the claim standing unenforced.

### F9 — Fingerprint format drift

Two variants circulate (`model=<basename>` vs `model=/full/path`, plus a
`mode_env=` legacy variant). Parsers use permissive `model=(\S+)`, so both
work — but the ledger can record a full path as model identity, and stricter
consumers would break.

**Fix:** canonicalize in the launcher (one format, documented); `tris status`
flags non-canonical lines.

### F10 — Permissions policy TOCTOU window

The mirror is hash-sealed and `validate` fails on drift — but validation
runs when someone runs it. Between a config edit and the next validate, the
guard enforces the OLD policy. Window is real and unbounded.

**Fix:** on `session_start`, the extension recomputes the hash (or shells
`perms-sync --check`) and warns loudly on mismatch. Cheap; closes the gap.

### F11 — Dispatch trust boundary wider than advertised — FIXED 2026-08-30

`dispatch_little_coder` accepts arbitrary `repo_dir` from tool arguments;
headless sub-coders run with effectively unrestricted shell
(permissions-guard covers edit/write/read only; write-guard blocks specific
shell patterns, not shell). Fine under the local threat model — but gateway
exposure (Telegram) would make a remote message able to steer a sub-coder
into any directory.

**Fix (before any gateway exposure):** approved-roots list
(`safety.dispatch_roots`) checked before spawn, with refusal events.

**DISPOSITION: FIXED 2026-08-30** — `repo_dir_allowed`: realpath
containment against TRIS_DISPATCH_ROOTS (colon-separated, default
~/Desktop/Projects; symlink escapes defeated — tested). Refusals emit
vb-gate events and NAME the resolved path (debuggable). Config key
mirrored at safety.dispatch_roots. Found + killed en route: two competing
F11 implementations from overlapping patches (the shadowing one made the
default root refuse EVERYTHING — including the primary workflow; its
silent refusal + an unbounded test wait produced the hang that led here).
Tests: 5 roots-gate cases incl. symlink escape; 43 bridge tests pass.

### F12 — Cockpit spawns two Python processes per 3-second tick, forever

Every poll runs `trismegistus validate --json` + `tris budget --json` as
subprocesses on the machine serving the model. Works, but permanent
avoidable CPU noise.

**Fix:** mtime-cached JSON payloads + longer interval, or a single snapshot
file written by `tris` that the cockpit reads.

### F17 — KV prefix-reuse contamination on this engine build **[NEW 2026-08-30, verified deterministic]** — MITIGATED, engine-side fix queued

Cross-session slot persistence (`--cache-idle-slots`, hardcoded in the
launcher) restored a prior session's KV; a later dispatch whose prompt
forked INSIDE the reused prefix (skill-inject grew the system prompt by
~500 tok; branch point at 6144) decoded STALE content — the probe session's
codeword answered unrelated dispatch tasks, deterministic 2/2, `success:
true` with no file created. Engine log evidence: task 105 partial reuse at
n_past=6229/6144 fork; direct curls (24-token prompts, no meaningful reuse)
always correct; pi-level repro 2/2; engine clean after mitigation.

**MITIGATION (shipped):** launcher gained `server.cache_idle_slots` profile
key (default on) + `cis=0` fingerprint marker intent; smoke profile sets it
off — repro sequence now answers correctly (probe canary → dispatch →
correct file, `accounting: session-usage`, cache_read 6144 live-slot reuse
still visible and NON-poisonous in this run). **Engine-side TODO (VITRIOL,
post-reboot, cert-suite):** minimal repro (reuse depth vs SWA window matrix
on 9B fa=on), root-cause against upstream PR #13194 semantics, cert test
"codeword canary across session boundary". NOTE: within-session reuse
(multi-turn tool loops) showed no corruption in any observed run; risk
class = cross-session restore + mid-prefix prompt mutation. This finding
STRENGTHENS RULES-CACHE-POLICY: prompt mutations are not merely cache-bust
cost on SWA models — they are a correctness hazard; residency design must
keep mutated content OUT of the reused prefix.
