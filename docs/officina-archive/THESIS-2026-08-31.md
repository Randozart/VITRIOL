## The vision, in one paragraph

The model is fixed by choice: Qwen3.8-27B, ~96K certified window, 11-12
t/s, RTX 3060 + GTX 1070 Ti. No VITRIOL optimization changes that physics,
so the leverage moves up a layer. Trismegistus is not "a harness that
tolerates a small window" — it is the harness engineered so that a 27B on
consumer hardware is a TRUSTWORTHY daily driver: the only stack where the
window is law (enforced, measured, dieted), reliability comes from
deterministic governance rather than model intelligence, and the engine is
a scheduling authority the harness is tightly integrated with rather than
a rented endpoint.

## The four commitments (why each layer exists)

1. **The budget is the product.** A 96K window with ~54K usable only works
   if every token earns its place: clear→compact→compress, the ≤8K
   fixed-overhead diet, lazy skill loading (M2), subagent digests (M5).
   Measurement discipline is central, not overhead — untracked context
   bloat is the one failure mode this hardware cannot absorb.
2. **Reliability from governance, not intelligence.** Cert gates, kill
   switches, deny-with-reason hooks (M3), executable permissions. The 27B
   does not reason about policy; the harness enforces it. A strong model
   with a sloppy harness loses to a weak model with a strict one on this
   rig.
3. **Tight VITRIOL integration is the moat.** Engine-as-authority, KV
   checkpoint/restore, /rewind, dispatch KV gates, fingerprint provenance.
   None of it is portable to a cloud agent — which is exactly why
   Crush/hermes/OpenCode cannot replicate the experience. The F1/F2/F11
   class of bugs are bugs BECAUSE integration is the thesis.
4. **Continuity over sessions.** Work and context survive interruptions
   (warm KV restore, rewind from one turn key) better than any component
   alone — this is the daily-driver property cloud tools approximate with
   session files and we get with slot state.

## Where Crush stands (control condition, not destination)

Crush v0.91.2 was dogfooded 2026-08-31 as the benchmark the dogfood day
grades against (docs/CRUSH-MINING-PLAN-2026-08-31.md). What we mine:
snappiness mechanics (small-model lane, lazy skills, hook semantics,
LSP-grounded edits). What we do NOT chase: ecosystem breadth, cloud
defaults, or features that weaken the budget. The winning claim is
"Crush-grade feel, at a fraction of the fixed cost, with continuity and
governance no cloud tool has."

## Success criterion

The owner reaches for `tris` before Crush for daily coding work — because
the 27B harness is more reliable per-token, keeps context across
interruptions, and enforces budgets the alternatives only observe. Graded
at the R3 dogfood day against the P1-P4 rubric (ROADMAP-2026-08-30).
